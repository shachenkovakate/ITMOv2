# Integration-проверки

Файл ведёт OpenCode. Обсудите с агентом содержание и проверьте предложенный diff. Все дополнения и исправления поручайте агенту в чате.

| Связь компонентов | Что может сломаться | Как воспроизводим | Ожидаемый результат | Подтверждение |
|---|---|---|---|---|
| FastAPI → `ReviewService` | Большой diff дойдёт до сервиса | Отправить 20 001 символ через `POST /api/reviews`, сервис заменить mock | HTTP 413, mock сервиса не вызван | HTTP-ответ и `call_count == 0` |
| `ReviewService` → LLM | Секрет останется в сформированном prompt | Отправить diff с тестовыми token, password и private key, перехватить вызов LLM | Исходных значений нет, вместо них `[REDACTED]` | Сохранённый аргумент mock LLM |
| `ReviewService` → LLM | Задержка или исключение зависнет либо даст неконтролируемый сбой | Настроить mock на задержку более 10 секунд и отдельно на исключение | Оба запроса завершаются контролируемым ответом | Время выполнения и форма ответа |
| LLM → API | Ответ потеряет структуру | Mock возвращает валидные `summary`, `risks`, `checks` | API возвращает ту же проверенную структуру, максимум три риска | Контрактный assert JSON |
| Логирование → наблюдаемость | В лог попадёт diff или ответ LLM | Выполнить запрос с уникальным маркером и перехватить записи | Маркера нет; допустимы только `request_id`, длительность и статус | Список полей перехваченной записи |
