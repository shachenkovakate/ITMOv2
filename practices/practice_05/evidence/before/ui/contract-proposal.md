# Предложение контракта команды UI

**Status**: Draft — awaiting human agreement  
**Дата**: 2026-10-27  
**Связь**: [UI specification](spec.md)

Независимое первоначальное предложение. Спецификация логики не читалась; договорённости между командами или с пользователем не утверждаются. Фиксированные требования источников отделены от предложенных решений.

## Зафиксировано источниками

- Один diff одного PR; существующая точка входа `POST /api/reviews`, поле `diff`.
- `API-1`: более 20 000 символов → HTTP 413 без вызова LLM.
- `REL-1`: ожидание LLM ограничено 10 секундами; ошибки контролируемые.
- `OUT-1`: `summary`, `risks`, `checks`; максимум три риска, каждый содержит `file`, `line`, `evidence`, `risk`.
- `SEC-1`: распознаваемые токены, пароли и приватные ключи удаляются до передачи модели.
- `QA-1`: риск подтверждается строкой diff либо применимым правилом Context Pack.
- `OBS-1`: журнал — только `request_id`, длительность, статус. `SCOPE-1`: решение по PR остаётся за человеком.

## Предложенный обмен

| Элемент | Предложение UI, ещё не согласовано |
| --- | --- |
| Вызов | `POST /api/reviews`, JSON `{ "diff": "исходный текст" }`; браузер обращается к службе приложения, не к LLM |
| Длина | Количество Unicode code points исходного текста; без trim/нормализации; UI и служба считают одинаково |
| Допустимость | Непустой, не только пробельный текст, максимум 20 000; UI не проверяет полную грамматику патча; служба принимает учебный diff с неполными hunk-счётчиками |
| Успех | HTTP 200; объект с `summary`, `risks`, `checks`; дополнительно `request_id` для связи с журналом |
| `summary` | Непустая строка; UI выводит буквально |
| `risks` | Массив 0–3 объектов; порядок служба определяет, UI сохраняет |
| `file` | Непустой относительный путь затронутого файла; UI не строит внешнюю ссылку |
| `line` | Положительное целое: новая нумерация для добавленной/контекстной строки, старая для удалённой; для риска по правилу — строка затронутого фрагмента, к которому применимо правило |
| `evidence` | Непустая строка: точная цитата строки diff с её префиксом либо явный ID правила Context Pack с объяснением применимости; нельзя вставлять необработанный секрет |
| `risk` | Непустая строка с описанием риска, без утверждения о невидимом коде |
| `checks` | Массив непустых строк; пустой массив допустим; UI не исполняет проверки |
| Неизвестные дополнительные поля | UI игнорирует; отсутствие обязательных или неверный тип → ошибка результата целиком |
| Ожидание UI | До 15 секунд; один активный запрос, без автоматического повтора; поздний ответ не меняет завершённый запуск |

Служба отвечает за содержательную проверку evidence и удаление поддерживаемых секретов. UI отвечает за форму, предварительные границы, проверку формы результата, безопасное отображение и состояния. Ошибка предварительной проверки не создаёт сетевой запрос, но служба независимо проверяет тот же вход.

## Предложенные ошибки

Единый безопасный envelope: `{ "error": { "code": "…", "message": "…" }, "request_id": "…" }`. Поле `message` не содержит diff, prompt, сырой ответ модели, ключ или stack trace. UI выбирает понятный текст по `code`, неизвестная ошибка получает общий безопасный текст. `request_id` формируется службой; для локальной ошибки формы или потери связи он может отсутствовать.

| HTTP / категория | Код | Поведение UI |
| --- | --- | --- |
| 400 | `INVALID_DIFF` | Исправить непустой diff; сохранить ввод |
| 413 | `DIFF_TOO_LARGE` | Показать лимит 20 000, сохранить ввод |
| 504 | `LLM_TIMEOUT` | Сообщить о превышении ожидания, разрешить ручной повтор |
| 502 | `LLM_ERROR` | Сообщить о недоступности анализа, разрешить ручной повтор |
| 502 | `INVALID_REVIEW` | Сообщить о некорректном результате; не показывать частичный ответ |
| Иной отказ службы | неизвестный код | Общая ошибка, идентификатор при наличии, ручной повтор |
| Нет ответа / 15 секунд UI | локальная ошибка связи/ожидания | Завершить loading, сохранить ввод, игнорировать поздний ответ |

Все HTTP-коды кроме 413 — предложения команды UI. Нельзя считать их согласованными только из-за включения в этот документ.

## Решения для будущего общего контракта

1. Подтвердить Unicode code points как единицу лимита. В источнике указаны только «символы»; UTF-16 и code points расходятся на части Unicode.
2. Подтвердить тип `evidence` и смысл `line`. Наш вариант сохраняет строковое evidence и исходные обязательные поля. Для более явного отображения старой/новой строки возможен отдельный `side`; это дополнительное поле пока не предлагается как обязательное. Номера строки самого diff — другой разумный вариант, требующий одинаковой реализации командами.
3. Подтвердить envelope/коды ошибок, `request_id` и разницу 10 секунд модели / 15 секунд UI.
4. Сопоставить критерии допустимого diff и редактирования секретов. UI не определяет regex или провайдера; общему контракту нужен конечный список поддерживаемых форматов секретов и ограничения, чтобы подсказка формы не обещала больше возможностей службы.

Это реальные неопределённости исходников, а не установленные конфликты команд. Новых экранов, истории, аккаунтов, GitHub-интеграции или выбора провайдера предложение не добавляет.
