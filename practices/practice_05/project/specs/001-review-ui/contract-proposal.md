# Результат согласования предложения UI

**Status**: Approved — aligned with CONTRACT v1.0 (2026-10-27)

Этот файл сохраняет прежнее имя для трассировки. Действующий источник — [общий контракт v1.0](../../../CONTRACT.md), одобренный пользователем «Тогда одобряю» ([свидетельство](../../../evidence/approval.md)). Первоначальное независимое предложение сохранено в [evidence/before/ui](../../../evidence/before/ui/); оно не переписывается.

## Принятые решения

- Один экран; idle/loading/success/error; во время loading поле и обе кнопки заблокированы. Ошибка сохраняет ввод. Повтор ручной, очистка возвращает фокус; изменение ввода скрывает прошлый результат.
- POST /api/reviews с единственным diff. 1–20000 Unicode code points фактического значения поля; пробельный ввод запрещён. UI проверяет непустоту/длину, backend — структуру.
- Summary 1–1500, risks 0–3, checks 1–10 непустых строк по 1–500 code points. Риск: ровно file, line, evidence, risk; file непустой, line целое > 0, evidence 1–20000 с точной цитатой очищенного diff и префиксом, risk 1–1000. Смысл вывода проверяет человек. Заголовок «Возможные риски».
- Line относится к новой версии для `+`/контекста и старой для `-`; UI подписывает сторону. Контекстное правило допустимо в описании risk, но не заменяет цитату и координаты.
- mode live/demo и непустой request_id приходят от сервера; demo видимо помечается «ДЕМО». Переключения режима клиентом и скрытого fallback нет. Дополнительные поля envelope игнорируются, нарушения обязательной формы отклоняются целиком.
- Ошибка: request_id и error.code/message; retryable отсутствует. UI показывает безопасный текст по согласованным кодам, для неизвестного кода — общий отказ. Полная таблица находится в общем контракте и [contracts/ui-interface.md](contracts/ui-interface.md).
- Бюджет модели 10 секунд, ожидание UI 15 секунд; поздний ответ завершённой попытки не меняет экран. Никаких автоматических повторов.
- Ключей модели, истории, хранения diff/ответа и выполнения рекомендованных checks в браузере нет. Конечный список маскирования и его ограничения перенесены в A-007 UI specification; маскирует backend.

## Что изменилось после первого draft

| Первоначальное предложение | Согласованный вариант |
| --- | --- |
| Пустой checks допустим | Требуется 1–10 проверок |
| Evidence могло содержать только правило | Каждому риску обязательны координаты и точная цитата |
| LLM_ERROR/LLM_TIMEOUT/INVALID_REVIEW | MODEL_UNAVAILABLE/MODEL_TIMEOUT/INVALID_MODEL_OUTPUT и полная таблица ошибок |
| Размеры текстовых полей не определены | Ограничения общего контракта |
| Подмена обозначалась без определённого поля | Обязательное mode live/demo |
| «Риски» и формулировка о подтверждении | «Возможные риски», без утверждения истинности вывода |

Открытых решений по интерфейсу нет. Реальная модель и её ключ настраиваются отдельно; они не требуются для реализации или честной demo-проверки UI. Выполнение проверок ещё не заявляется.
