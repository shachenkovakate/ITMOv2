# Phase 0 research — UI

Основание решений: утверждённый CONTRACT v1.0, спецификация UI и заданный координатором стек. Исследование фиксирует выбор реализации, а не новые продуктовые требования; неразрешённых вопросов нет.

## Decision: статические файлы, один origin

**Rationale**: один экран не требует сборщика; FastAPI уже обслуживает API и сможет отдавать HTML/CSS/JS. Относительный /api/reviews исключает дополнительную конфигурацию origin и ключи в клиенте.

**Alternatives considered**: SPA-framework и отдельный dev server добавляют зависимости, которых нет в выбранном стеке.

## Decision: code point count фактического textarea.value

**Rationale**: перебор строки по Unicode code points соответствует контракту, в отличие от обычного string.length для emoji. Размер проверяется до trim; trim применяется лишь для проверки пустоты, исходная строка отправляется неизменной. Textarea не ограничивается HTML maxlength, который считает иначе и может обрезать вставку.

**Alternatives considered**: длина UTF-16 или байтов нарушает принятую границу; нормализация перед счётом расходится с входом сервера.

## Decision: последовательный request lifecycle с номером попытки

**Rationale**: loading блокирует ввод и кнопки; AbortController и 15-секундный таймер завершают ожидание. Монотонный идентификатор попытки и активный флаг проверяются перед любым изменением UI, включая finally, поэтому поздний ответ или завершение старого запроса не разблокирует новый. Таймер очищается при любом финале. Автоматических повторов нет.

**Alternatives considered**: только abort недостаточно описывает гонку уже завершённого запроса; глобальный флаг без номера может принять ответ старой попытки.

## Decision: строгая клиентская проверка формы, серверная проверка доказательства

**Rationale**: клиент проверяет обязательные типы, размеры, mode, request_id, точные поля риска и префикс evidence. Совпадение очищенной цитаты с координатами проверяет сервер: у браузера исходный, ещё не очищенный diff. Ошибка схемы не даёт частичный success.

**Alternatives considered**: дублировать parser/redactor в браузере создаёт две расходящиеся политики; доверять любой форме ответа нарушает UI-границы.

## Decision: literal DOM и доступные статусы

**Rationale**: динамический текст записывается через textContent; элементы создаются DOM-методами, а не innerHTML. Статус announced через role=status/aria-live; ошибка связана с textarea и объявляется через alert. Фокус перемещается только при локальной ошибке ввода или явной очистке, а не при асинхронном завершении.

**Alternatives considered**: markdown rendering и автоматические ссылки здесь не нужны; цветовой статус без текста недоступен.

## Decision: фиксированные безопасные сообщения по code

**Rationale**: серверный message и произвольный текст ошибки не отражаются в UI. request_id показывается только как проверенная непустая строка; mode demo отмечается рядом с результатом. Неизвестный code получает общее сообщение и возможность ручного повтора.

**Alternatives considered**: echo текста провайдера раскрывает внутренние данные; retryable не входит в принятый контракт.
