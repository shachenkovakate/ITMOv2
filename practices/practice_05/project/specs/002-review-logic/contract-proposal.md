## Принятые отличия от первоначального draft

- Каждый риск имеет обязательные непустой file, положительный целочисленный line и точное evidence с префиксом строки. Null-координаты и RULE-only evidence исключены. Правило можно объяснить в risk.
- checks содержит 1–10 непустых строк. Возможные риски — 0–3; цитата не означает истинность вывода.
- Ошибка содержит только request_id и error с code/message; retryable не передаётся. Принята таблица HTTP-кодов общего контракта.
- Unicode code points, частичные учебные hunks, новая нумерация для добавлений/контекста и старая для удалений сохранены.
- Служебные request_id/mode добавляет сервер. Ответ модели строгий; дополнительные служебные поля UI может игнорировать.
- Один вызов модели, общий бюджет 10 секунд; клиент ждёт до 15 секунд. Автоматических повторов и скрытого fallback нет.
- После разбора ответа выполняется маскирование строк, затем окончательная проверка структуры и evidence по очищенному diff. Проверять evidence только до последнего маскирования недостаточно.

## Редактирование секретов и приватность

Согласованное покрытие SEC-1 по CONTRACT.md v1.0; не гарантия обнаружения любых секретов:

- Значения в одной строке после `=` или `:` у ключей `token`, `password`, `passwd`, `secret`, `api_key` без учёта регистра; ключ может быть обёрнут в одинарные/двойные кавычки, пробелы вокруг разделителя разрешены. Для строкового значения в кавычках заменяется содержимое до соответствующей закрывающей кавычки; для значения без кавычек — последовательность до пробела, запятой, `;` или конца строки. Пустое значение остаётся пустым. Экранированные кавычки внутри такого значения должны учитываться.
- Значение credentials после слова `Bearer` и пробела, до пробела/кавычки/конца строки.
- Отдельные токены с префиксами `ghp_`, `github_pat_`, `sk-` и последующими не менее 8 символами из букв, цифр, `_`, `-`.
- Блоки от `-----BEGIN PRIVATE KEY-----`, `-----BEGIN RSA PRIVATE KEY-----`, `-----BEGIN EC PRIVATE KEY-----`, `-----BEGIN OPENSSH PRIVATE KEY-----` до соответствующего END. Каждый непустой payload строки заменяется отдельно, сохраняя количество строк и префиксы diff; если END отсутствует — маскируются все оставшиеся payload строки diff. Структурные заголовки diff остаются для навигации, содержимое ключа не отправляется.

Значения заменяются на `[REDACTED]`; совпадения ищутся и в добавлениях, и в удалениях, и в контексте. Одинаковые правила применяются к ответу модели. Маскирование не охватывает произвольные обфускации, неизвестные форматы и секреты, неотличимые от обычного текста. Перед реальным анализом используются учебные данные, не реальные ключи.

Приложение хранит исходный и очищенный ввод только в памяти обработки попытки, без истории и файлов дампов. Ключ провайдера задаётся вне браузера и репозитория. Журнал приложения содержит только request_id, duration_ms и status; body, prompt, headers и response не логируются. Политика хранения у выбранного внешнего провайдера не задана и не должна выдумываться.
